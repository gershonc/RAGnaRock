1. Purpose & example questions

The customer-experience team asks open-ended questions answered only from retrieved reviews plus their metadata (park, visitor country, visit date, rating). The system deliberately couples metadata filtering (exact, auditable) with dense retrieval (semantic, fuzzy) so questions that mix “who / where / when” with “what did they feel” work in one call.

  • What do visitors from Australia say about Disneyland in Hong Kong?
  • Is spring a good time to visit Disneyland?
  • Is Disneyland California usually crowded in June?
  • Is the staff in Paris friendly?
  • How did ratings for Hong Kong trend in 2015–2017? (uses the years filter)

Without OPENAI_API_KEY, ask returns extractive snippets (no synthesis). With a key it returns a grounded summary with Review-ID citations.

3. System architecture

Two phases share the Chroma collection. Offline builds it once; online filters + searches it per question. rag/config.py + .env supply paths and the optional OpenAI key.

LayerRoleLives in
Metadata filtersNarrow by branch, reviewer_location, month, yearrag/filters.py
Dense retrievalSemantic match on review text (crowding, staff, weather, rides…)rag/retrieve.py + Chroma
Document prefixMetadata embedded into each chunk so similarity aligns with structured fieldsrag/ingest.py
RelaxationDrop constraints stepwise so sparse combos still return evidence (noted in output)rag/retrieve.py: _relax_filters
GenerationLLM summarizes retrieved reviews only, cites Review IDs; fallback lists snippetsrag/answer.py

4. Ingest pipeline

ingest_csv(csv_path, reset=False, batch_size=256) streams the CSV (a line-count pre-pass exists only to size the progress bar), converts each row, and flushes to Chroma every 256 docs. One bad row can never abort the run: rating/date parse failures get safe defaults and are counted.

python -m rag.cli ingest --reset
# → "Indexing reviews: 100% 42656/42656" then "Indexed 42656 documents into Chroma at .chroma/"
# Re-run after data changes; always --reset after the season-label fix.

Park-local seasons (Fix 4)

California and Paris use meteorological Northern-Hemisphere seasons. Hong Kong is subtropical (Hong Kong Observatory climatology: long hot summer, short autumn), so September counts as summer there and autumn is October–November only. Filtering always happens on month numbers — season names are just the user-facing shorthand.

9. Retrieval & relaxation

retrieve(question, n_results=20) embeds the question with the same MiniLM model, issues collection.query(query_texts=[q], n_results=k, where=…), and packs id / document / metadata / distance per hit. If a strict filter yields nothing, it retries with progressively weaker filters — first non-empty result wins, and every dropped constraint is recorded.

10. Answer generation & context budget

answer_question(question, hits, filters) has three exits: no hits → fixed message; key set → _answer_openai; no key → _answer_extractive. Context is capped at 12,000 chars — whole review blocks are added until the next would overflow.

system: You are an analyst for Disneyland guest reviews.

11. Worked end-to-end traces

Trace A — fully constrained (the Figure 4 example)

Q: "What do visitors from Australia say about Hong Kong Disneyland?" -k 20

interpret_query → branch=Disneyland_HongKong, location=Australia, months=None, years=None
where → {"$and": [{"branch": "Disneyland_HongKong"}, {"reviewer_location": "Australia"}]}
Chroma → N hits (CA/Paris/AU-other rows excluded before ranking)
answer → grounded summary citing e.g. (670772142), (670607911)

Trace B — season + relaxation path

Q: "Is spring a good time to visit Disneyland?"   (no park mentioned)

interpret_query → branch=None, months=[3,4,5] (all parks use the same spring)
where → {"month": {"$in": [3,4,5]}}
if zero hits → notes would accumulate; normally spring is well covered (10,051 rows),
so the strict query returns and no relaxation is printed.

Trace C — sparse combo showing every stage

Q: "What did visitors from Malta say about HK Disneyland in winter 2011?"

interpret_query → branch=HongKong, location=Malta, months=[12,1,2], years=[2011]
attempt 1: all four clauses → likely 0 hits → note "Dropped reviewer_location…"
attempt 2: HK + winter + 2011 → maybe 0 → note "Dropped month/season…"
attempt 3: HK + 2011 → maybe 0 → note "Dropped year…"
attempt 4: HK only → hits → answer carries 3 notes; LLM is told evidence was relaxed,
so it must hedge ("limited evidence…").

13. Fixes 1–5 (applied 2026-09-29)

Fix 1 — Month matching used substring search ✓ fixed

Before: "may" in query fired on “maybe / may be”. After: word-boundary regex for all month names/abbreviations/seasons (Fig. 6); may requires capital May or month context; abbreviations supported. File: rag/filters.py: infer_months.

Fix 2 — One bad row killed the whole ingest; full CSV held in RAM ✓ fixed

Before: rows = list(reader) then bare parses — one Year_Month="oops" aborted 42k rows. After: streaming read, per-row try/except with safe defaults, skip-counters (Fig. 2). File: rag/ingest.py: ingest_csv.

Fix 3 — Metadata duplicated in LLM context ✓ fixed

Before: context pasted the whole stored doc under a metadata header (prefix twice). After: _review_body() shows body only (Fig. 9); handles legacy Season (NH) and new Season (park-local) prefixes. File: rag/answer.py.

Fix 4 — Single NH season model for all parks ✓ fixed

Before: September = autumn everywhere. After: park-local seasons via BRANCH_SEASON_TO_MONTHS (Fig. 7); HK summer = Jun–Sep, autumn = Oct–Nov; ingest labels Season (park-local); month inference takes branch. Files: rag/metadata.py, rag/filters.py, rag/ingest.py.

Fix 5 — Branch substring matching; dead years field ✓ fixed

Before: if alias in s (“paris” ⊂ “comparison”); years always None. After: longest-first \b regex; new infer_years() (1990–2030, ranges) wired into interpret_query, where, relaxation (Fig. 8), and CLI output. Files: rag/filters.py, rag/retrieve.py, rag/cli.py.

Verification: py_compile clean; assertion suite covers branch boundaries (“comparison” → None), modal-“may”/“maybe” → None, “Jan” → [1], HK summer → [6,7,8,9], year ranges, relaxation chain length 5, single-occurrence metadata in context. (System python here is 3.9, so rag/metadata.py carries from __future__ import annotations for X | None syntax.)

15. Evaluation & troubleshooting

Evaluation layers

#LayerWhat to measure
1Gold Q&A set30–80 hand-written questions (branch × location × season × staff × crowding) with reference answers or must-cite Review IDs.
2Retrievalrecall@k / nDCG: did the right reviews appear in top-k? Slice by filtered vs relaxed queries.
3AnswersLLM-as-judge groundedness, relevance, faithfulness + human spot-checks; penalise uncited claims.
4Metadata stressQuestion pairs differing only by branch/month must change filters and answers (use show-filters diffs).
5Ablationsdense-only vs +filters vs +relaxation; attribute gains per layer.

Troubleshooting

  • Hugging Face / proxy errors on ask: after one good ingest the model loads offline (local_files_only=True); else try unset HTTP_PROXY HTTPS_PROXY.
  • Slow first ask: cold load of MiniLM takes 1–2 min; later runs in the same shell are faster.
  • Sparse combos: expect relaxation notes (country + park + month); the answer should state limited evidence.
  • Re-index after these fixes: season labels and doc prefixes changed → run python -m rag.cli ingest --reset once.

Known limitations / future work

  • Location allowlist covers ~42 of 162 CSV locations; consider fuzzy matching or deriving the list from the data.
  • Ratings are stored but never used for filtering/ranking; a “low-rating only” intent is currently semantic-only.
  • No per-review language detection; non-English reviews embed poorly with MiniLM.
  • No eval harness or gold set checked in yet — §15.1–5 is the plan, not the implementation.
